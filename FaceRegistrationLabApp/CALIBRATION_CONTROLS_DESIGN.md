# Adjustable intrinsics: implementation contract

Authorized by the request to create a calibration app with adjustable focal lengths and principal points and saved values. This is a bounded patch to the existing Face Registration Lab and its control panel. The inherited 640×720 attachment, centered camera-relative controls, Full Space Mixed, Stage style 1, zero-sized SpatialML container and app-owned mesh remain the structure. No new module or window model is needed.

The default is Custom, initialized from C or a validated saved custom profile. Preserve original A/B/C/D as comparison presets. Custom keeps C's source-to-virtual affine fixed and edits effective virtual `fx`, `fy`, `cx`, `cy` independently. The user requested a simpler control after trying the original four-row layout. Show one parameter at a time. A full-width built-in Button cycles fx/fy/cx/cy; a descriptive label and read-only numeric Text identify the selection. Built-in Decrease/Increase Buttons adjust it by the chosen 0.5/5/25-pixel step, a full-width Slider handles coarse changes, and an Adjustment step Button cycles the increment. Direct text entry and NumberField are removed. Selection is kept in LabUi and does not change calibration values or revision. Reset C, Load saved and Save values actions sit below. Capture tools and previews are available in the existing panel through a section switch. Scrolling handles overflow within the inherited panel.

Use existing PicoTheme and component colors, built-in hover/haptics, transparent layout regions and the existing attachment surface. No app-authored background, border, custom color or custom interactive component is introduced. Existing controller state stays in FaceRegistrationLab; pure values/validation live in LabIntrinsics and JSON/AtomicFile persistence in LabCalibrationStore. This sample's shared-source architecture is retained rather than restructuring unrelated scene/graph code.

Settings changes apply between completed graph frames. Capture requests pin mode, values and revision; edits while an old frame runs cannot authorize a save with new settings. Custom K is virtual and must not be multiplied by the image affine again. Every custom capture records requested values and actual effective K. Frame capture queues without requiring two consecutive measured frames, validates a usable matching frame and reports timeout/rejection reasons.

Save values is independent of camera/face readiness. Save an archived JSON profile and external latest profile under app files/RegistrationLabProfiles, and keep an atomic app-private copy for automatic reload. Validate ROM, image dimensions, affine, finite values, positive focal lengths and matching scalar/matrix values when loading. Do not clear data or delete older profiles/captures/recordings. No commit is authorized.

Verify parameter independence and frame-revision matching with shipped JS/Kotlin fixtures, profile JSON roundtrip and invalid-profile rejection, meaningful queue/timeout state regressions, both app builds/lint/format, APK assets and the SpatialUI style/patch checks. Device acceptance must include applied custom K and a saved/reloaded value profile, with a real face capture reported separately from no-face plumbing. The current knowledge query returned Unity 6.0 cards, so Kotlin API details are grounded in the installed 6.1.9 artifacts and existing compiled SDK usage.

The single-demo exception is recorded in `FaceLandmarkerApp/.scratch/architecture_waiver.json` with the reason: this bounded control-panel extension shares an existing app-owned 3D Stage sample and preserves its lifecycle/controller; values, storage and UI already have separate files. The architecture checker downgrades layout findings but still fails its mandatory ViewModel check. The generic patch scanner also fails inherited entry/manifest assumptions. These failures are preserved in validation evidence; neither checker is represented as passing. The calibrated app is not being restructured into a generated application template as part of this panel change.

Host checks and the local APK are complete. After initially requesting build and instructions only, the user authorized installation. Replacement install, installed APK hash, startup, Custom mode and fresh camera frames are verified. Control interaction, persistent save/load across real app launches, a new positive-face capture and physical alignment remain unverified.
